# S1 / S1b · Alarms (board M0-04, M0-05)

**Status:** code merged in parts (PR #8 logic, part 2 runner); device results wait on Setup Desk Part D. Owner: Planner Engineer.

## Design
- CoachCore owns the logic, with no iOS imports: `PlannedAlarm`, the `AlarmRegistering` protocol, `AlarmReconciler` (plan vs registered: re-set missing, cancel dropped, ignore past) and `TestAlarmSchedule`. Unit-tested in `AlarmReconcilerTests`.
- The app owns AlarmKit: `App/Alarms/AlarmKitRegistrar.swift` implements `AlarmRegistering` (authorisation, `AlarmManager.alarms`, `schedule(id:configuration:)` with a fixed date, `cancel(id:)`). Plan ids are AlarmKit ids, so comparison is direct.
- Every app open reconciles against the stored plan (plan §4.1). No background job.
- The plan and its alarm ids are stored on the phone (`UserDefaults`) when "Set test alarms" is tapped and never regenerated by a reconcile, so S1b compares the same ids before and after an update.
- Safety: a plan with nothing upcoming never cancels anything (CoachCore rule, unit-tested), and a stored plan that can't be read stops the reconcile with a warning instead of running it.
- "Clear later test alarms" on the Spike tests screen cancels the 13 alarms set 21+ days out, in case M2 slips.
