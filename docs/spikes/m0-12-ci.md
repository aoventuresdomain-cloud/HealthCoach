# M0-12 · GitHub Actions CI

Two workflows, so the expensive macOS minutes go only where they must.

| Workflow | Runner | Runs on | Does |
|---|---|---|---|
| `core-tests.yml` · **CoachCore tests (Linux)** | `ubuntu-latest`, container `swift:6.2-noble` (pinned) | every PR and push to `main`; skips docs/Markdown-only | `swift test` in `CoachCore` |
| `app.yml` · **Build app (iOS 26 simulator)** | `macos-26`, newest Xcode 26 | PRs only; skips docs/, Content/ and Markdown-only; manual runs | `xcodebuild build` of app + embedded `LiveActivity.appex`, `CODE_SIGNING_ALLOWED=NO`; screenshots when `App/`, `LiveActivity/`, `Shared/` or the screenshot recipe change, or on a manual run |

Both cancel an older run when a newer push lands on the same branch. Screenshots (`.github/scripts/screenshots.sh`) are the `simulator-screenshots` artefact (30 days): Spike tests screen, Live Activity layouts, timer running, and the real Live Activity in the Dynamic Island.

## Blocking merges
The repo is private on GitHub Free, which has **no branch protection or rulesets for private repos**, so GitHub can't stop a red merge. The block is by process: the Head of Engineering, the only one who merges, merges only when both checks are green. No GitHub Pro.

## Minutes (free plan, spending limit £0)
Free plan: 2,000 minutes a month for private repos. Linux counts 1×, macOS 10×. With a £0 limit, runs stop when minutes run out; nothing is charged.

| Job | Per run (estimate, cold) | Runs a month (guess, M1–M4 pace) | Billed minutes |
|---|---|---|---|
| Linux core tests | ~3 min (image pull ~1, build + test ~2) | ~60 (PR pushes + main) | ~180 |
| macOS app build + UI tests (M1-01) | ~9 min | ~20 PR pushes | ~1,800 → **180 macOS min** |
| macOS screenshots | +~3 min | ~10 | ~300 → **30 macOS min** |

Rough total ≈ 180 + 1,800 + 300 = **~2,300 billed minutes**: just over the 2,000. Budget as **about 18 macOS runs a month (~1,700 billed) plus Linux freely (~300)**.

Levers if it runs hot, in order: open a PR only when the work is ready (each push to an open PR is a macOS run); iterate on CoachCore by running **Core tests** manually on the branch (Actions › Core tests › Run workflow, 1× minutes) before opening the PR; batch small UI changes into fewer PRs.
