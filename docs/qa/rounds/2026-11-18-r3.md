## How this round runs

- The rows are ordered by risk: R1 first, because a wrong calorie or load change is the only thing here that could hurt the CEO. If time runs short, R4 is the part that shrinks.
- **Evidence:** the CoachCore tests come from the CI Core run on the round SHA. The shots and UI tests come from one `app.yml` run with screenshots and publish_shots on, with the shots read from `qa/gate-0a-shots`.
- **Severity:** blocker, major, minor, trivial. A row in R1 or R2 that fails on a limit (100 kcal step, 1,850 weekly floor, 1,700 day floor, 150 g protein, 24 kg) is a blocker.
- **Rule for every test:** a test that was skipped, weakened or has had its expected values loosened since main at 760b230 counts as a fail.

**CI baseline** (from #105's green run 44314041187 at 25785f8, 18 Nov): the app job took 25 min in all, and the UI suite was **38 tests in 960 s (16.0 min)**, with 1,047 s from start to end of testing. The slowest tests were Onboarding (188 s), AlarmPermission (118 s), WorkoutPlayer Upper A (81 s) and Today week 1 (67 s). The job's timeout is now 60 minutes. SundayPrompt is timed with the ease model, 8.5 s against a 20 s budget, with simulator wall time kept only as a diagnostic.
