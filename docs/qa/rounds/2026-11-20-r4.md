## How this round differs from R3

- **It's reported as the CEO's weeks, not by engine area.** Each section is something the CEO does or sees. A row passes only when the screen they see is right; a CoachCore test passing underneath is the evidence for it, not the result.
- **One build, everything.** Core changed in both waves, so every Gate 1+2 row (`docs/qa/gate-1-2-checklist.md` §A, §C5) re-runs on this SHA, along with the R3 rows and the rows below.
- **Ease is measured:** every daily job runs through the ease-budget helper (`docs/qa/ease-budget-method.md`).
- **The rule for every test** is the same as R3: a test that was skipped, weakened or loosened counts as a fail.
- **Cut items:** for anything cut by the cut order (N11, N10, in-store mode, the compare slider), the round records "cut" and checks that nothing half-built shows on screen.

## Hygiene

- All the round 2 and R3 UI tests pass on this SHA. The phone-deferred list in the pack is unchanged, or has grown with N7's camera parts.
- Privacy: the app makes only two kinds of network call. One is the Open-Meteo forecast (`OpenMeteoClient` in `App/Planner/MorningWeather.swift`), which uses fixed Hyde Park coordinates and constant query items, so no health data goes out. The other is the shop link in `MealsHubView.swift`, which the CEO taps. Exercise GIFs are bundled and nothing fetches them. The Reminders write is local, not a network call. The network-API scan test from #117 enforces this allowlist, and QA also reads the diff since 6332a80.
- Known issue from #117, with the HoE: notifications don't follow a pending Preferences edit until the next re-plan. J5.2 records it until it is fixed or accepted.
